## 分阶段执行与恢复

不使用pipeline时，可以分别把以下命令放进 `systemd-run --user ...`；不要在同一输出目录并发启动两个控制器：

```bash
bash scripts/run_scale_4gpu.sh resources
bash scripts/run_scale_4gpu.sh smoke --gpus 2,4,5,7 --allow-shared-gpus --gpu-memory-utilization 0.80 --wait-for-gpus
bash scripts/run_scale_4gpu.sh preflight --workers 2
bash scripts/run_scale_4gpu.sh run --split dev --gpus 2,4,5,7 --allow-shared-gpus --gpu-memory-utilization 0.80 --wait-for-gpus
```

`prepare`、`status`、`report`不启动GPU。`resources`不启动GPU，`smoke`会四卡加载模型。环境失败重试使用 `preflight --retry-failed`，旧尝试会移入 `preflight_attempts/`；一旦数据用于正式模型评测，禁止再改变这些环境选择。

完成的模型结果（包括失败）原样保留，不重复采样挑成功。中断或取消的未完成任务可用明确选项归档后重试：

```bash
systemd-run --user --unit=sca-scale4gpu-dev-20261024-resume1 \
  --working-directory="$PWD" \
  /usr/bin/bash scripts/run_scale_4gpu.sh run --split dev --gpus 2,4,5,7 --allow-shared-gpus --gpu-memory-utilization 0.80 --wait-for-gpus --resume-interrupted
```

源码第一次模型检查时冻结在输出目录 `runtime/`；数据、补丁、测试元信息和仓库指纹在正式运行前校验。更改配置或实现做新实验时，用新的 `--output`；不要修改冻结runtime。
