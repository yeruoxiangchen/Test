## 2. 项目目标与实际实现

目标是完成可演示、可评测的 Agent 开发项目：用户提供代码截图或终端报错截图、问题描述和代码仓库，系统提取截图证据，检索源码，修改代码，运行测试，依据反馈继续修复，最后输出补丁及独立验证结果。

最初讨论过 mini-swe-agent；实际交付与以下全部实验基于 **CoreCoder 0.8.0**，固定提交 `bd64cfe7ad2789fa0ab1b3a689ad160567b5cdb0`。复用其 Agent 决策循环、上下文压缩和工具接口，未修改上游决策循环。来源及复用边界见 [UPSTREAM.json](../UPSTREAM.json) 和 [实现说明](implementation.md)。不能将当前实现描述为已经完成的 mini-swe-agent 扩展。

本项目实现截图注册与裁剪、准确文本/CPU OCR/VLM 三路读取、隔离仓库工具、预算与后台运行管理、数据构建、补丁导出及干净副本重放。模型均为现成模型，没有 SFT、RL 或新策略训练。界面截图修复尚未纳入当前验证范围。

主程序使用独立 `.venv`，本地模型使用 `.model-env`，历史仓库使用项目专属 Python 3.9 依赖前缀。仓库代码和测试运行于 Bubblewrap，无网络、无 GPU，测试受只读保护。视觉和代码模型配置可独立替换；本轮实际均使用 Qwen3-VL-8B-Instruct。没有修改 ChartQA 或其他项目的环境、代码与任务。

**工具格式与上下文。** [上游压缩器](../vendor/CoreCoder/corecoder/context.py) 只对大于 1500 字符且超过 6 行的工具消息进行一级裁剪。当前[沙箱包装](../src/screenshot_agent/sandbox.py)和[工具返回](../src/screenshot_agent/tools.py)把 worker 结果再次 JSON 编码，大量源码换行在外层文本中表现为转义。这 722 条原始工具消息均符合“跳过一级按行裁剪”的条件。此统计检查的是结构条件，不是在每次压缩调用时重新执行上游，不能据此计算因果收益或声称每条消息都实际触发过压缩。

**编辑错误。** worker 返回的源码本身可以正确解码出换行；没有证据证明 worker 损坏了源码。模型构造错误的多行编辑参数是直接观测，多层转义是否促成这些错误仍需新版本对照。严格唯一匹配应保留，不能靠未经核对的模糊替换掩盖错误。

**停止状态。** [本地服务](../scripts/local_model_api.py)目前在没有解析到工具调用时统一返回 `stop`，未准确区分长度截断；[CoreCoder 主循环](../vendor/CoreCoder/corecoder/agent.py)收到无工具文本便结束。例如 `pytest-7220 / oracle` 一次输出达到 2048 token，无源码工具、无补丁，仍记录 `submitted`。独立验证没有把它算成功；问题在执行与终止状态的表达。

典型证据：[pytest-7220 OCR 的重复编辑](../outputs/v5_supplementary/extended/three_readers/evaluation/runs/pytest-dev__pytest-7220_ocr/events.jsonl)、[oracle 提前结束结果](../outputs/v5_supplementary/extended/three_readers/evaluation/runs/pytest-dev__pytest-7220_oracle/result.json)。准确文本也仅 1/50，说明视觉读取之外还有明显瓶颈，但这些描述性统计不能单独区分工具、模型、定位和预算各自的因果影响。
