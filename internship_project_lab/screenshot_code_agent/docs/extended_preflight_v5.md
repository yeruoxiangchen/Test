# 扩展数据预检与适配边界

候选在模型调用之前固定：50 个主候选加 10 个有序 SymPy 环境备选，排除旧的 10 个任务。按原仓库确定内部开发/测试组后，从 Issue 中提取原始代码/输出块生成截图。最终 52 个通过预检，按原顺序取 50 个；全部 60 个及其失败状态均保留。

进入评测的条件是：错误版本能产生官方解析器可识别的失败计分项，参考补丁后官方 FAIL_TO_PASS / PASS_TO_PASS 全部满足，且两次测试均未超时。该条件检验当前适配环境的可评测性，不检验模型修复难度。

## 环境与测试

每个任务复制专属 Python 3.9 依赖前缀，源码安装在无网络、无 GPU 的 Bubblewrap 中完成；仅构建时允许写自己的前缀。运行 Agent 和测试时，依赖前缀只读。没有复用或修改其他项目环境。

SymPy 官方评分项只有函数名，保持官方 `bin/test -C --verbose ...` 命令。其他仓库按官方计分项提取全部测试文件，再运行 `python -m pytest -rA`；Sphinx 去除 tox 打包和非测试 fixture 参数，包在预检前已离线安装。官方日志解析器和评分器未修改。并非原始 Docker 执行协议。

历史 pytest 的自举测试禁用第三方插件自动加载，避免当前 xdist 的参数 API 与旧 pytest 冲突。所需 flit 构建后端安装在新项目依赖前缀；数值库依赖固定。锁定需求、实际 freeze 和每题前缀的配置文件保留。

Pylint 源码含两个内部文件符号链接。构建器验证链接不越界、不成环、指向同一归档内的普通文件，再将内容实体化为普通文件；Agent 仓库不包含链接。这是已记录的源码导出适配，可能影响专门测试链接语义的完整上游测试，当前没有宣称运行完整上游测试套件。

## 预检恢复历史

第一轮任务 checkout 路径少了一层 `tasks/`，尚未完成有效预检；整个目录保留为 `swebench_extended_v5_setup_path_failed/`。第二轮保留 14 个有效任务，并发现 SymPy 评分名称误当路径、插件冲突、构建依赖和内部链接问题。修复后，仅将失败目录与其专属前缀移到 `preflight_attempts/`，保持 60 个候选和顺序不变，再做第三轮预检，得到 52 个可评测任务。

这些恢复全部发生在扩展集首次模型调用之前。当前 50 题的清单、截图、问题和预算已冻结；不会根据修复率替换任务。尚未支持的候选可以在将来的新数据版本中单独适配，再独立评测。
