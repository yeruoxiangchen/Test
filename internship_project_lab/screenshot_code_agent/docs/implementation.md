# 第一版实现与复用边界

## 结构

- `config.py`：任务、模型和预算协议；只保存 API 密钥的环境变量名。
- `models.py`：兼容 Chat Completions 的适配器；保留 CoreCoder 的响应契约。
- `control.py`：共享费用预留、调用计数、取消和结构化事件。
- `images.py`：允许列表图片注册、裁剪、准确文本 / CPU OCR / VLM 读取。
- `tools.py`：与 CoreCoder 工具接口连接；实际文件操作和 shell 均进入 Bubblewrap。
- `worker.py`：隔离环境内部运行的标准库文件工具。
- `sandbox.py`：网络/进程/文件系统命名空间、只读运行时、命令资源与超时控制。
- `repository.py`：私有错误快照、独立工作区、补丁导出和干净副本重放。
- `runner.py`：编排上述模块，调用未修改的 CoreCoder Agent 主循环。
- `data.py`：20 个自编合成微型任务、实际错误日志采集、图片渲染和参考补丁审核。
- `report.py`：同题结果、读取字符错误及失败统计。
- `cli.py`：单任务、批量任务、后台、状态、停止、报告。

## 关键设计

视觉读取返回纯文本证据，代码模型无需直接处理图片消息。两个模型可独立替换。
首次整图读取在 Agent 启动前统一进行，三组使用相同的截图内容范围；之后可以调用裁剪/复读工具。
读取不确定项原样返回，不自动用参考源码修正 OCR。

所有任务文件工具运行在沙箱内部；仅隔离 bash 而在主机运行 read/edit 会留下文件访问缺口，
因此本项目替换整组仓库工具。截图处理在受控注册表中按图片 ID 操作，模型不能指定任意主机图片路径。
原始仓库、参考补丁和转写文件不挂载给 Agent。

私有 baseline 从不执行任务测试。初始复现在单独 baseline_check 中进行，避免测试副作用污染重放基准。
Agent 工作区中 `.git` 和 protected_paths 从私有 baseline 只读绑定。
补丁收集包含被新 .gitignore 忽略的新增文件；导出前拒绝符号链接和受保护文件变化。
验证器重新复制 baseline、检查并应用补丁，然后执行固定测试命令。

模型工具执行可能并发，预算和事件有锁，文件修改及 shell 使用同一修改锁。
退出预算使用独立于普通 Exception 的终止信号，避免被 CoreCoder 的可恢复工具错误分支吞掉。
模型请求失败也保留保守费用预留，避免反复错误调用绕过费用统计。

## 首版贡献说明

本项目没有重新实现 CoreCoder 的 Agent 主循环，也没有训练视觉模型。
自己的工程实现是截图工具、统一隔离工具后端、任务/费用控制、独立补丁验证、数据构建和结果分析。
成功测试不代表唯一正确补丁；允许语义等价的修改，结果以固定测试覆盖范围为边界。

## 后续扩展接口

现有 Tool 接口可以新增项目依赖运行时或诊断工具；Model 适配器可替换为本地推理服务。
将来接入 RL 时还需 token 级轨迹、环境重置和训练器对接；当前 JSON 对话记录不等于 RL 训练轨迹。
