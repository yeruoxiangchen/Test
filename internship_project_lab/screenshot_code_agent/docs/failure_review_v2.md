## synthetic_leap / vlm：仓库搜索循环耗尽步数

错误版本：`leap(year)` 仅判断能否被 4 整除，导致 1900 年被判为闰年。
准确文本组与 OCR 组均通过；视觉组未生成补丁，状态为 `unresolved`。

### 可观察证据

- 视觉转写保留了关键失败信息：`self.assertFalse(m.leap(1900))` 与 `AssertionError: True is not false`。
- 代码模型第一次响应正确解释了世纪年必须能被 400 整除的规则，说明关键问题信息已进入其上下文。
- 随后进行了 **11 次 glob 文件名匹配**，尝试 `*leap*`、`*calendar*`、`*date*`、`*year*` 等名称，
  其中多次重复。它没有使用文件内容搜索工具寻找函数定义。
- 第 11 次模型调用读取评分测试，才从 `import miniapp as m` 得知模块名；第 12 次调用搜索 `*miniapp*`。
- 在读取源文件和编辑前达到统一的 **12 次代码调用上限**。另外有 1 次视觉调用、13 次工具调用，总耗时 42.852 秒。
- `patch.diff` 为 0 字节，独立验证记录为 `No patch produced`，没有执行最终补丁测试。

因此，该次可观察的失败发生在仓库检索与动作选择阶段。关键截图内容已经可用；
不能仅凭它属于 VLM 组就将其归因为 OCR/视觉识别错误。
准确文本与 OCR 的两次成功修改均补充了 `% 100`、`% 400` 判断，并通过干净副本测试。

### 诊断价值与后续候选

事件记录能区分“已经理解问题”“找到相关文件”“实际修改代码”和“通过独立测试”。
这里的空补丁与检索循环不会被 Agent 的自然语言解释计为成功，步数限制也终止了重复查询。
后续可以评估工具说明或重复空结果反馈是否有帮助；任何改动都应使用新的实验版本，
在相同任务与预算下重新比较，不能回填本轮结果。

## synthetic_transpose / ocr：已读到正确源码但重复读取

OCR 保留了 `def transpose(rows)` 和错误实现 `return list(zip(rows))`，关键代码字符正确。
Agent 随后的 **12 次工具动作全部是读取同一个 `miniapp.py`**，没有编辑或执行修复测试。
其重复解释主要讨论不等长矩阵，而任务本身要求矩形矩阵；最终达到 12 次代码调用上限。

实际耗时 138.467 秒，13 次工具调用包含 1 次初始截图读取；空补丁导致最终验证没有执行。
此例的文件定位已经成功，可观察问题是修复推理与动作停滞，不能归为未找到源码或关键字符识别错误。
重复动作反馈可以作为后续开发候选，本轮保持统一调用预算和原始失败结果。

原始目录：`outputs/full_eval_20261022T054515Z/evaluation/runs/synthetic_transpose_ocr`。

## synthetic_csv_fields / ocr：未闭合工具调用导致第二次修改未执行

OCR 将 `text.split(' ')` 读为 `text.split('')`，丢失了引号中的空格。
Agent 随后读取真实源码，已经确认实际是按空格切分，并将分隔符修改为逗号。
固定测试继续失败：结果含 `' b'`，仍缺少字段去空白处理。

代码模型下一次响应准确指出需要逐字段 `strip()`，并生成了一个 `edit_file` JSON。
但文本包含 `<tool_call>` 开始标签而没有 `</tool_call>`，本地协议解析器没有将其转换为可执行调用；
CoreCoder 收到没有工具调用的响应后结束该轮会话。

实际只发生 4 次代码调用、4 次工具调用，完成 token 合计 471，未耗尽 12 次调用预算。
已导出的补丁只有 `split(' ') → split(',')`，独立重放成功、最终测试失败。
因此，该次失败同时包含读取差异、初次修复不完整，以及未闭合协议输出导致的中断；
不能将全部原因概括成 OCR 读错，也不能把自然语言中提出的修改视为已经执行。

后续候选是为未闭合工具调用增加明确的协议错误反馈，让模型在原有预算内修正；
当前批次保持原解析器和相同条件，不在中途改写实验。

原始目录：`outputs/full_eval_20261022T054515Z/evaluation/runs/synthetic_csv_fields_ocr`。
关键文件包括 `events.jsonl`、`result.json`、`patch.diff` 与 `verification_test.log`。

## boltons_copy_function_kwdefaults：输出预算与截图文件名错误的两条失败路径

本题的准确文本组未生成补丁：代码模型只调用一次，输出达到单次 **1024 token** 上限，
长篇解释和整段替换 JSON 在中途结束，工具调用未闭合。它在读取仓库或运行测试前就提出了
`__module__`、`__qualname__` 等属性假设，未验证实际失败的关键字默认值问题。
因此，不能将该组的失败归于截图读取；准确文本输入也可能在修复推理和协议输出上失败。

视觉组的第一步则确有读取错误：截图实际文件名为 `boltons/funcutils.py`，
视觉转写与 `file_hints` 变成了 `boltons/functools.py`，且没有标记不确定性。
Agent 读取错误路径后得到 `FileNotFoundError`；后续文件清单中已经包含正确的 `funcutils.py`，
但它没有核对该相似名称，而是对字面路径 `boltons/*.py` 重复调用内容搜索。
该工具将路径当作实际文件/目录，返回空匹配；模型最终耗尽 12 次调用，仍未编辑。

这是一条“截图文件名读错 → 仓库核对未恢复 → 搜索参数不合适 → 步数耗尽”的可观察轨迹。
视觉组没有使用剩余的裁剪或复读机会。改进候选包括截图文件名核对、明确搜索路径错误，
以及未闭合/截断工具输出的反馈；需要用新实验版本验证效果。

OCR 组通过了独立验证：读取源码和测试后补充了 `__kwdefaults__`，同时保留普通复制行为。
本轮三组条件相同，没有为失败组增加预算或重跑替换结果。

原始目录前缀：`outputs/full_eval_20261022T054515Z/evaluation/runs/boltons_copy_function_kwdefaults_`。
分别保留 `oracle`、`ocr`、`vlm` 的模型请求、工具反馈、补丁和测试记录。

## boltons_one_to_one_empty_update / oracle、ocr：替换片段不匹配

准确文本组与 OCR 组都把问题定位到双向字典更新函数，但生成的整段 `old_string` 与真实代码不一致。
准确文本组尝试编辑 6 次、OCR 组尝试 5 次，均收到
`old_string must be nonempty and match exactly once; read more context`。
中间虽有源码读取，后续仍提交同类不匹配片段，没有产生有效修改。

两组均消耗 12 次代码调用，耗时分别为 118.561 秒、140.325 秒，最后为空补丁。
准确文本组达到循环步数上限；OCR 组触发共享代码调用预算限制。
这个拒绝行为保证了不匹配的片段不会被猜测性替换，也说明正确读取报错和知道大致修复方向仍不足以执行有效编辑。
该例主要暴露精确编辑与错误反馈使用能力，不属于测试环境无法运行。

最终视觉组也出现同类失败：关键报错和 `dictutils.py` 路径已读到，但生成的替换片段仍与源码不一致。
它消耗 12 次代码调用，耗时 174.385 秒后触发共享调用预算，未生成补丁。
至此，本轮 8 次未通过运行均有原始证据和上述人工复核记录；修复成绩未因复核而改变。

## CSV 事后边界检查：通过固定测试仍可能偏离参考行为

准确文本组和视觉组的 CSV 补丁通过了原固定测试，但使用了过滤空字段的实现。
参考补丁则会保留连续逗号以及首尾逗号产生的空字段。
为检查这项差异，在新副本中增加了三项事后测试：`a,,b`、`,a`、`a,`。
所有检查都在 Bubblewrap 内执行，没有修改原始任务、评分测试和结果。

| 实现 | 原测试通过 | 三项空字段检查通过 | 原测试与补充检查均通过 |
|---|---|---|---|
| 已知参考补丁 | 构建时已验证 | 是 | 是 |
| 准确文本组补丁 | 是 | 否 | 否 |
| OCR 组补丁 | 否 | 是 | 否 |
| 视觉组补丁 | 是 | 否 | 否 |

准确文本组和视觉组将 `a,,b` 转换为 `['a', 'b']`，参考行为为 `['a', '', 'b']`。
OCR 组保留空字段，但仍缺少原测试要求的去空白处理。
原问题描述也没有明确规定空字段语义，因此这同时暴露了规格不够清楚和测试未覆盖分歧。
仅凭原测试无法判断这项边界行为是否符合任务作者的期望，读取 CER 也不能替代语义验证。

这些检查在观察结果后才加入，只作为数据质量审核，不回填或替换本轮预先确定的主指标。
下一版数据应先明确空字段语义并增加相应测试，再冻结数据重新比较。
