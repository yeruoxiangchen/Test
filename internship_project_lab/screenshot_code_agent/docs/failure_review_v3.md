# 官方来源小规模实验的失败复核

2026-10-22。固定 10 个 SWE-bench Lite 任务，其中 9 个通过环境预检，完成 27 次模型修复运行。仅 `pytest-dev__pytest-5227` 的准确文本与视觉读取两次通过官方 FAIL_TO_PASS / PASS_TO_PASS 检查。三组均使用同一代码模型与预算。

本轮使用可见、受保护的官方测试和适配 Python 环境，不属于官方 Docker 隐藏测试排行榜。Pytest 是内部开发组，SymPy 是内部测试组；四个可运行 SymPy 任务三路均失败。不能用这九题推断视觉功能提升了真实仓库修复成功率。

## 观察到的瓶颈

| 案例 | 可核对的轨迹 | 能得出的结论 |
|---|---|---|
| Pytest 5103，准确文本与 OCR | 读取截图后仅一次代码模型调用，输出达到 1024 token；工具调用 XML 未闭合，没有执行仓库检索或产生补丁 | 工具协议/输出长度已阻止修复；准确读取也不能解决这一问题 |
| Pytest 5227，OCR | 截图长 SQL 行丢失、空格合并；随后请求 14 次 grep，包括正确的 `src/_pytest/logging.py`，没有编辑 | 同时存在读取损失和文件检索实现问题，不能把失败单独归因于 OCR |
| Pytest 5413，视觉读取 | 八次读取 `src/_pytest/_code/code.py`，没有编辑；准确文本组也没有产生补丁 | 找到相关文件不等于理解函数并完成修复，不能把文件命中率当作修复能力 |
| Pytest 5495 | 多次读取 assertion 文件、部分编辑尝试，仍未通过；有多次达到输出上限的响应 | 重复读取、编辑失败和预算占用需要分别查看工具返回；工具请求次数不等于成功编辑次数 |
| Pytest 5692，准确文本与视觉读取 | 重复查阅 ini/配置文件，未形成有效修复 | 检索路径偏离目标；日志中的 Unicode NEL 还暴露了报告解析问题 |
| SymPy 11897，视觉读取 | 18 次 glob，请求耗尽步骤，没有文件读取和编辑 | 图像字形修正并未解决仓库导航循环；不应将该失败包装成 OCR 问题 |
| SymPy 12419，准确文本与视觉读取 | 仅有初始截图读取，没有仓库工具请求，直接返回 | Agent 的结束状态 `submitted` 不是成功；必须依靠外部测试与评分 |

逐次计数来自 `scripts/analyze_official_failures.py`，输出到 `trace_diagnostics.json`。达到输出上限只作为截断线索：当前本地服务统一返回 `finish_reason=stop`，不能据此声称它准确报告了截断原因。没有将以上人工观察扩展成未经验证的“定位错误率”。

## 两个运行工具问题与一项日志问题

1. `grep(path="文件名")` 原实现对文件调用目录递归，静默得到空集合；不存在的文件和通配符路径也返回空结果。修复为直接扫描字面文件，并对缺失路径返回可操作错误，提示先用 glob 查文件。
2. 原补丁导出阶段 `git add -A -f .` 将 pytest/字节码缓存强制纳入补丁。修复为在暂存、差异导出和变更文件列表中使用相同排除规则，同时保留新增、删除和修改的源码。原始补丁仍保留，另导出 `patch.clean.diff` 并从干净基线重放，未使用参考补丁或模型调用。
3. 事件采用合法 JSONL，但字符串中包含 Unicode NEL。`str.splitlines()` 错把它当作记录边界，导致第 27 次运行后汇总失败。修复为按物理 JSONL 行解析；对 NEL、U+2028、U+2029 做回归测试。恢复报告时校验全部原始结果、事件和补丁的 SHA-256 不变。

这些修复先在独立源码副本中通过 19 项相关测试。27 次对照运行保持原实现；在冻结报告与源码归档后才更新交付源码。另有一题开发集 OCR 回归单独记录在 `docs/post_benchmark_fixes_v3.md`，不进入三路对照的分母。

## 输入质量与运行事故

初版 CodeOCR 图像的 DejaVu Sans Mono 不覆盖四份代码中的中文注释，画成了方框。相同十份代码、相同参考文本改用固定的 Noto Sans Mono CJK 字体，审计所有可见字符后重新读取。旧图像与 40 次旧读取保留作诊断，不用于主指标。新读取的视觉 CER 在 1×/2×下分别为 1.05%/1.03%，CPU OCR 为 5.39%/8.22%。这是读取结果，不代表修复结果。

SWE-bench 中一张图的数学字符 `ℯ` 在对应题任何一组模型接收前更换了字体，原图和指纹保留；三次实际输入像素均需与修正图一致。没有依据解题成败更换题目。

CodeOCR 40 次结果已保存后，维护者修改了仍在运行的 Bash 启动文件，触发结束阶段解析错误，最终显存统计未采集。修复主批次的显存统计也因汇总异常未采集。两个异常均有显式恢复记录；模型已退出，没有借用其他批次峰值。后续运行时不修改活动脚本和运行源码。

`sympy__sympy-11870` 的完整三角函数测试超过预检时间上限，保留原始记录；它属于环境/预算不可用任务，不属于模型失败，也不从原始选择清单消失。

## 当前贡献与范围

已实现的是截图读取、裁剪重读、隔离仓库工具、受保护测试、预算控制、轨迹记录、补丁导出与独立评分的工程系统，以及固定数据来源、按仓库分组和三路可复现对照。视觉读取工具接入既有 CoreCoder 执行循环；没有修改其决策策略，也没有 SFT/RL。

代码读取优于本次 CPU OCR 的证据已经具备；真实大型修复上的提升尚未证明。当前九题、两个仓库、合成截图和小模型/短预算不足以支撑泛化结论。下一轮应先在开发组验证这些工程修复及工具协议，再冻结新版本与新测试任务，避免在已查看的测试组上持续调参。
