## 1. 建议确定的任务与路线

静态场景的一组 RGB 图像，以及跨帧身份一致的可见实例 mask，输出可单独编辑的多个完整物体 mesh 和各自的场景位置、旋转、尺度。目标首先限定为至少在部分输入帧中可见的实例；始终不可见且没有 mask 身份的物体，不能从这些输入唯一确定。

建议保留物体级生成表示，把推断从独立生成改为邻近实例之间的协同生成：

```text
共享 RGB 帧 + 跨帧实例 mask
  ├─ 共享相机/粗几何估计 → 场景坐标与物体位置初值
  ├─ 共享整帧特征 + 各物体局部图像特征
  └─ 输入侧可见性、邻接与相对位置证据
             ↓
每物体独立 TRELLIS.2 latent + 共享权重
             ↕
带世界坐标和实例身份的邻居信息交换
             ↓
SS → Shape-SLat → 独立 mesh
             ↓
放回共同场景，联合检查/校正可见 mask、遮挡与接触
```

外部不增加 GT 深度、点云、物体 3D box 或位姿要求。相机和粗几何可以内部使用冻结 VGGT 或 SfM 获取；VGGT 是一个可替换的前端，关系模块和 TRELLIS.2 的方法定义不依赖 VGGT 名称。现有 HSSD 受控实验使用已知相机和目标 canonical frame，必须与真正 RGB+mask 推断分开报告。

纯 RGB 场景通常存在整体尺度不确定性。所有物体共享同一个尺度规范，不能逐物体单独配准后宣称恢复了正确场景布局。

## 3. 原生 latent 是第一项工程工作

优先选少量固定 HSSD 训练对象，包含薄结构、椅/桌腿及相互遮挡对象，完成：

```text
同一原始完整物体 mesh
  → 保留场景变换，烘焙镜像/非均匀缩放，规范化
  → 官方 Flexible Dual Grid 几何转换
  → 官方 Shape encoder 的原生 latent
  → 官方 Shape decoder
  → canonical mesh / world mesh / 输入相机叠加图
```

Shape-512 标签为活动 `32³` 坐标及 32 通道特征；旧 TRELLIS-v1 的 8 通道 SLat 不可 reshape、补零或换 decoder 冒充 T2 标签。DINOv2 旧特征也不能直接当作 DINOv3 条件。

SS 有一个容易混淆的例外：官方 T2 工具仍使用 TRELLIS-v1 的 SS encoder，张量同为 `8×16³`；因此不能笼统说所有 SS 编码器都不同。但是 T2 的 SS 标签输入来自原生 Shape 支持坐标。现有准备说明按 Shape-1024 的活动 `64³` 坐标构建 SS 标签，推断时再将 SS decoder 的 `64³` 支持 max-pool 到 Shape-512 的 `32³`。旧 SS 只有在支持坐标、编码器权重、规范坐标和编码约定逐项相同时才可能复用，不能以张量尺寸相同作证明。首批采用官方链路重新生成，避免语义混用。

512 几何训练需要 Shape-512 标签；为沿用当前官方 SS 准备路径，还会生成 Shape-1024 支持。这不等于首轮要训练或运行高分辨率 1024 Shape Flow。

T2 原生几何编码直接处理 mesh/dual grid，不沿用旧 SLat 的“150 个干净视图→DINO 特征融合”标签构造。现有共享场景 RGB 继续作为条件输入；为新 T2 标签无需再批量补一套旧式 150 视图。

验收包括坐标往返、轴向、crop/K、latent 归一化和 token/support 对应，以及解码 mesh 的同视角外观与表面误差。区分 raw mesh→O-Voxel 的离散误差、VAE 编解码误差和生成模型误差。继承官方 Shape-512 8192 token 过滤规则时必须记录覆盖率与失败对象；不能静默截 token 或事后删除困难目标。旧项目的 IoU 阈值不直接充当新 codec 的已验证标准。

相关代码：[官方 Shape 编码](../TRELLIS2/data_toolkit/encode_shape_latent.py)、[官方 SS 编码](../TRELLIS2/data_toolkit/encode_ss_latent.py)、[官方 SS→Shape 推断](../TRELLIS2/trellis2/pipelines/trellis2_image_to_3d.py)、[现有数据准备说明](DATA_PREPARATION.md)。

## 4. 关系模型具体应改变什么

### 4.1 共同世界坐标，独立物体 latent

每个物体保持自己的规范坐标与原生 latent；以 `x_world = T_i x_local` 查询图像和邻居信息。跨物体关系使用相对位置、尺度、观察方向和可信度；不直接平均不同物体的 latent。对称物体的旋转、遮挡导致的尺寸低估都属于待估量，输入侧的 box/pose 不是 GT。

第一版先在明确的已知位姿条件下验证生成结构，同时保持 RGB 前端接口。之后加入估计位姿以及与真实前端误差相符的扰动，验证真实输入。GT 相机、完整 mesh、隐藏表面仅作监督或单列诊断；测试条件不得从 GT 偷取完整范围或邻居隐藏几何。canonical 约定变化时应重新生成相应标签，不能随意旋转 latent 特征。

### 4.2 物体特征与场景上下文并存

局部目标 crop 提供足够分辨率的纹理与轮廓；原始完整帧提供桌椅、遮挡者和背景关系。全场景相机/粗几何只计算一次，不对每个被抠黑的目标图重新估计独立场景坐标。

保留跨帧一致的实例 ID，把 `other` 拆成可识别的邻居和其余背景。对一个三维查询点至少区分：目标可见表面证据、射线前方可信空域、被指定邻居挡住而未知、无有效观测。投影进入目标 mask 并不能证明它位于目标表面；投影到邻居 mask 也不能证明目标在该点不存在。

mask 提供可见所有权，本身不提供整条射线的完整物体顺序。前后关系须结合多视图、估计深度或当前生成表面；按视图/射线表达，保留不确定性，不固定成“整场景 A 永远在 B 前面”的排序。

### 4.3 在生成过程中交换信息

建议第一版每个训练组 2–4 个同场景邻近对象，主干权重共享；同组使用同一个 flow 时间 `t`，每物体保留独立噪声与 latent。根据输入共视、邻近/遮挡证据建立稀疏边。

从各物体当前 noisy state 和局部观测提取少量带位置的关系 token，通过零初始化残差注入目标 denoiser。关系层先放在少数 block，SS 与 Shape 两阶段都保留可用接口：SS 决定粗支持，Shape 决定后续几何细节。实施顺序可以先 SS 后 Shape，但不能用 SS 改善代替最终 mesh 改善。

第一实现可在每个采样步先从全部对象的同一时刻状态生成紧凑关系缓存，再逐个对象调用共享 denoiser并同步提交更新。这保留协同条件，又允许沿用 batch-one 主干；它需要新的场景级调度，不是目前代码已有功能。更深层的跨对象 hidden-state attention 可在资源允许后增加，不预设必须让整场景所有高分辨率 token 做全连接 attention。

邻居条件在训练和推断中都必须来自可用观测、预测或同一时刻的 noisy state，不能训练时读取邻居干净 GT latent、推断时却换成有误差预测。可加入邻居缺失/错误及 pose 扰动增强。关系边不是硬几何裁切，错误邻居不能永久删掉目标的可能表面。

### 4.4 联合渲染与空间约束

把物体 mesh 放回同一场景，用共同深度排序得到每个实例的可见 mask，与输入 mask 对比。椅子被桌子挡住的像素，允许生成的椅背在桌面后方；单独渲染椅子得到的完整轮廓不应被强行压成输入的残缺可见轮廓。建筑及未选中实例仍可能遮挡，需保留背景几何/深度上下文及无效区域处理。

训练首版以原生 latent flow matching 为主，使邻居关系真正进入形状生成。联合可见性最先用于固定预测 mesh 的位姿/尺度校正和评估；若进一步加入对 Shape 的渲染损失，需要单独验证 decoder/渲染器的梯度与内存，而不是把不可导统计写成有效训练 loss。低频 endpoint 约束可以后续引入，初版不每个优化步解码整场景高分辨率 mesh。

接触/支撑只在证据支持的物体对上约束。非穿透优先基于解码表面及可靠内部判定；T2 支持开放表面，而 SS 是表面支持，不是实体占用，因此不能直接惩罚 SS 重叠、包围盒重叠或照搬依赖闭合实体的 SDF loss。桌腿与椅腿的包围盒重叠完全可能是正确布局。

## 5. 数据如何复用与调整

现有 HSSD 数据的完整 mesh、场景布局、共享照片、相机、实例元数据与 16/4/4 场景划分可复用；旧 latent 与 DINO 缓存保留为旧模型实验资产。

新增一个场景分组索引，每个样本记录：

```text
scene_id / split / 共享 frame_id
instances: instance_id, 可见 mask, crop/K, 原生目标路径
input_pose: 估计 object_to_world、来源、可信度
supervision_pose: 训练 GT（禁止测试条件读取）
neighbors: 实例对、关联帧、输入侧关系证据、有效性
background: 未建模实例及建筑的可用观测
```

当前照片输出针对候选对象提供 mask，不能先假定它覆盖所有需要重建的邻居；应按分组检查缺项后补齐。组队优先从已选同场景对象中建立，不重新拍摄每个对象。现有对象可见帧选择并不保证对象对有充分共视与遮挡，先统计覆盖率；若不足，用新版本计划补充，保留旧分母。

先用 2–3 个训练场景内约 8–12 个对象做 codec 与协同生成开发；数量是下一阶段建议预算，尚未冻结清单。对象按输入与几何类别规则选择，不能按生成成绩选容易对象。通过执行检查后转现有 128/32/32 留出结构验证，192 仍是第一批泛化试验，不等于论文最终数据规模。

不要求一开始把场景所有装饰件都当作训练目标。初期学习有关系的对象对/小组；大场景推断用邻接图遍历和共享状态覆盖所有合格实例，输出覆盖率须单独报告。若将原背景对象提升为新的 GT 训练目标，必须重新检查资产家族和跨划分出现关系，不能沿用旧192的无泄漏声明。

## 6. 对现有 LaRI、VGGT 和运行任务的处理建议

- **LaRI**：保留多视图对齐、射线可见性及不把遮挡当空域的经验。旧“固定候选深度→多层交点”的预测器暂不设为 T2 主线依赖；以后只有在完整系统获益时再接入，不能因目录名而强制保留。
- **VGGT**：若使用，承担共享相机/可见粗几何初始化；估计深度不等于隐藏面的 GT。关系模型同时利用多视图特征和实例生成状态，避免又变成仅对 depth/confidence 权重做循环诊断。
- **HSSD192 当前准备**：既有冻结协议和队列不被本设计修改、停止或重启。其旧式标签服务于 TRELLIS-v1 结果留档。建议下一笔新增 GPU 预算优先用于 T2 原生小样本闭环，不再把完成所有 v1 编码和新一轮 v1 长训设为迁移前提。若决定改变在跑队列的边界，另行明确执行并记录。
- **存储**：建议新产物放 `/data/zjr/pose_constrained_trellis2/`；旧 HSSD 通过只读路径映射引用。运行前设置 TMPDIR、TORCH_HOME、HF_HOME、HF_HUB_CACHE、TORCH_EXTENSIONS_DIR、MPLCONFIGDIR 等到该项目 /data 路径。此次仅写 Tracker 的小文档，尚未创建大数据目录或启动程序。

## 7. 实施顺序与评价

| 次序 | 工作 | 需要得到的证据 |
| --- | --- | --- |
| 1 | 固定少量 HSSD 对象，原生 T2 编码/解码，实际短训与完整采样 | 标签可用、投影/尺度正确、两阶段执行成功；不能只看 1-step 或 loss |
| 2 | 跑通 T2 多视图独立物体重建并回放到场景 | 可使用的同骨干 base，单物体/整场景 mesh 图；不要求每对象完美过拟合 |
| 3 | 场景分组、邻居 token、SS/Shape 关系注入、联合可见性校正 | 真正使用邻居预测状态的完整候选；训练/推断条件一致 |
| 4 | 未见场景主对照，随后补真实 RGB+mask 场景 | 完整方案 vs base 的总体效果、遮挡区域和布局；单独报告真实前端误差 |

首轮只做 512 几何，SS 与 Shape 分阶段加载/训练，冻结 VAE 和主干主体，使用已有 adapter/LoRA 路径及小型关系层；PBR 与 1024/1536 推断之后再做。24GB 卡可行性通过实际有用的少步运行记录确认，不能从官方 H100 时延或 CPU 测试推断，也不做分配式显存探测。长任务提供启动/监视命令交用户监视。

主对照建议使用同 TRELLIS.2 后端的多视图独立重建 base；阶段2的产物可以直接复用，不新增一串逐模块实验。ReconViaGen v0.5 是另一个已经发布的多视图/T2 实用参照，需明确它是 ReconViaGen SS + T2 Shape 的混合路线，不把它写成全原生 T2 SS。旧 yxc30k 可以留作纵向参照，但跨骨干总收益不能全部归为关系模块。

以完整方法相对 base 的平均效果和实际 mesh 作为继续标准。不强制所有对象、seed、指标及单模块消融都赢；若论文声称某个模块导致收益，再补支撑该因果表述的最小证据。

评估至少同时覆盖：物体完整表面 CD/F、可见与被遮挡区域、共同坐标下场景布局与实例可见 mask、合理的穿透/接触统计、覆盖率、耗时/显存，以及固定相机的整场景与逐物体图。物体规范空间的形状评价和世界空间评价分开；禁止逐对象 ICP 修正布局后作为场景主分数。RGB 尺度规范需要对齐时，只允许预先规定的全场景一次对齐，优先由相机估计对应确定；给定 GT 位姿的受控实验不额外拟合变换。

| [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) | 原生 sparse latent、形状与材质分阶段生成 | 作为几何先验和原生 codec；迁移本身不等于新贡献 |
| [GenRecon](https://arxiv.org/html/2605.23888v1) | 多视图投影到 T2，重叠场景块在共同 latent 中协同生成 | 已有场景一致性；我们关注带实例身份的独立完整物体及其关系，不能泛称首次共同坐标/联合生成 |
| [WorldSculpt](https://arxiv.org/html/2609.05416v2) | 多视图、canonical-to-world、逐实例补全与场景组装 | 很接近输入输出；跨实例形状/位姿耦合是应具体比较的差别 |
| [MIDI](https://arxiv.org/html/2412.03558v2) | 单图多物体 latent 同时去噪、跨实例 attention | 借鉴生成中交换信息；本项目重点是多视图的三维位置与可见性约束，不能把普通跨实例 attention 写成首创 |
| [ObjectSDF++](https://arxiv.org/html/2308.07868) | RGB/mask、共同场景透射率、遮挡感知实例监督 | 借鉴可见性逻辑；其 SDF 实体假设不能直接套到 T2 表面支持 |
| [MessyKitchens / MOD](https://arxiv.org/html/2603.16868v2) | 利用多物体形状/位姿信息修正物体位姿 | 提醒区分联合位姿修正与联合形状生成，不把二者混称 |
| [ReconViaGen v0.5](https://github.com/GAP-LAB-CUHK-SZ/ReconViaGen/tree/v0.5) | ReconViaGen 的多视图 SS 接 T2 Shape/Texture，多图融合 | 可作发布模型参照；不是新提出的跨实例关系生成器 |

可检验的核心研究问题：**给定同一组场景照片和实例 mask，多物体的可见性与空间关系，能否帮助生成各自完整、可编辑且相互一致的 mesh？**

“换 TRELLIS.2”“加 scene graph”“加普通 cross-attention”都不足以单独证明创新。上述设计是待验证的研究假设；贡献强度取决于具体关系表示、如何影响生成，以及未见场景结果。首先做可用的完整系统和主对照，再围绕实际有效的部分组织论文。
