显存按 PyTorch allocator 的峰值统计：单卡 SS 新数据约 3,006.97 MiB，SLat 约 2,915.40 MiB；
双卡几何训练每卡约 1,165.98 MiB。NVIDIA-SMI 的整卡占用可能包含其他任务，不能当作本模型
显存。此前观察到的约 16GB 整卡占用不应归因于 V2 几何模块。

恢复后原始权重不是 bit-exact：CUDA `grid_sample` backward 使用原子累加，实测差异为少量
FP32 舍入单位；CPU checkpoint/optimizer/RNG 单元测试通过。工程验证检查 `atol=1e-8`，
不会把这种数值一致性误写成完整 CUDA bit-determinism。

主要实现文件位于 `v2/`、`data_v2/` 和本实验目录。第一版 `native_ss.py`、`frozen_slat.py`、
`contracts.py` 已逐文件与第一轮 Dev64 冻结 plan 的 SHA-256 比较，全部完全一致。V2 使用
子类和独立契约实现，不需要修改第一版训练/推理源码。

本轮定位并处理的问题：

- 相机矩阵、射线与投影不能被 BF16 autocast 降精度；V2 几何运算固定 FP32。
- 本环境 implicit-GEMM 在 `cumm.tensorview.from_numpy` 触发 SIGFPE；使用公开支持的
  `SPCONV_ALGO=native`，没有修改外部库。历史审计也记录过同一故障。
- 冻结 SLat 启用 deterministic mode，而 CUDA float cumsum 在该版本不可用；V2 对少量层
  使用固定顺序前缀/后缀加法。
- 大数据集按样本首次使用前校验 hash，避免仅测试两个对象也先重读整个 2K 缓存。
- 所有输入视图及 image context 统一选择；推理按白名单排除 amodal mask、GT 层和 latent。
- 新增层截断 overflow；旧标签不知真实 overflow 的 capped rays 按保守删失标记处理。
