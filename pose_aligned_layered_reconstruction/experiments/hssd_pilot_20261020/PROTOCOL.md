# HSSD16 扩大前验收协议

建立：2026-10-20 UTC。独立于正在执行的 Formal2K；不修改其数据、训练器或父模型。

## 目的与样本

验证原始物体资产在既有 TRELLIS v1 SS/SLat 表示下能否正确编码、解码和学习。
这是训练对象上的工程诊断，不是新物体/新场景泛化结果，也不是论文最终主表。

从已下载的 HSSD 场景 102344049 固定选取 16 个不同资产实例。名单在
`outputs/hssd_pilot_20261020/plan.json`；选择发生在任何新 latent/模型分数产生之前。
包含椅子、桌子、沙发、柜体、床等，以及非均匀缩放和镜像实例。
同源拆分资产家族会保留标识；这批对象不划分伪独立测试集，不扩大到其余资产。

## 数据契约

1. trimesh 读 GLB 内部节点变换，先烘焙实例形变，再执行 Habitat Y-up 到 Z-up
   和统一尺度规范化。场景刚体位姿独立保存。镜像不进入相机旋转。
2. Blender 独立导入同一原始资产，不能重复转换坐标轴。两套读取器的规范化
   顶点集合双向最近距离最大值 < 3e-5。比较完整顶点集合，不只比 AABB。
3. 干净目标用官方 TRELLIS 配方：150 个 Hammersley 视角、半径 2、40 度 FOV、
   512 RGBA、Cycles 128 samples、官方灯光。vendor 文件保留原始源码和 SHA-256。
4. 官方 Open3D 三角面相交体素化，64³ 表面支持，不填充内部。主训练环境
   Open3D 0.18 + NumPy 2.0 存在已复现段错误；体素化单独在既有 foundpose
   环境的 Open3D 0.18 + NumPy 1.23.5 执行。不修改共享环境。
5. SLat 标签采用 DINOv2 ViT-L/14-reg 的 x_prenorm 去 CLS/register，禁止额外
   LayerNorm；RGBA resize 后黑底合成；与官方相同的 grid_sample 和跨视图均值。
   特征保存为 FP16 后以 FP32 输入冻结 encoder，sample_posterior=False。
6. SS 与 SLat 使用相同支持集合，coords 与 feats 的行对应关系不重排破坏。
   不同视图组共用同一目标文件；几何形变不同不得按资产模板盲目共用。
7. 输入来自原始完整房间和全部实例摆放。RGB 用原场景预览灯光的 Cycles32，
   深度/ownership 用 nvdiffrast。双方统一 opaque 策略，逐输入视图独立核对
   Cycles object-ID mask 与 nvdiffrast mask，IoU 必须 >= .95。
   不使用之前移除天花板的展示图作为训练输入。
8. 物体所在房间多边形内选择相机，检查目标不截断、有足够可见像素和相机净空。
   同相机生成 clean/occluded 对，每对象 8 视图。逐视图可见率完整保存；不保证
   这批选择已覆盖所有真实遮挡程度或多视图联合不可见面积。
   2026-10-20 修订002：先尝试原60°、32方位、距离1.3/1.8/2.5倍物体最大尺寸；
   仅当几何候选或通过可见性/净空检查的候选不足8个时，依次尝试60°/75°/90°、
   64方位、距离0.8/0.95/1.1/1.3/1.55/1.8/2.1/2.5倍的固定搜索表。
   高度仍为世界坐标1.25/1.65米；不改变房间、8像素边距、正深度、可见像素、
   可见率或净空阈值。首个成功候选池按原规则选8个不同机位，不跨焦距重复计数。
   clean/occluded及所有模型对照共用所选K/w2c；每次搜索和拒绝结果单独存档。
   此修订发生在第4个对象场景准备失败后、任何16对象训练前；前三个成功对象
   使用原池即可通过，已完成数据不重写。原协议/源码与本修订分开保存。
9. 既有 LaRI 输出中心深度 ±2。含范围外交点的射线显式取消监督，记录有效比例；
   不改变原始交点，不用无法预测的远墙深度强迫拟合。

## 独立关卡

- 坐标：上述顶点一致性 + 原始 mesh 的 nvdiffrast silhouette 与 Blender alpha
  在 4 个固定视角比较，每视角 IoU >= .95。
- SS：原支持 → SS encoder → decoder，IoU >= .90，沿用现有工程门。
- 新 SLat：冻结解码 mesh 对原始 mesh，在规范化原坐标中 20K 点计算 CD/F-score。
  预先设定工程筛错门为 Chamfer-L1 <= .015，F@.02 >= .85；不是论文通用保证。
  任何对象失败均记录并停止训练，不删除失败对象后汇总 PASS。
- 每物体输出 RGB/原 mesh/解码 mesh 同相机图库。数值通过不代替外观和薄结构检查。
- 训练可学习性：完整 25 步采样后与父模型同噪声比较，不以 flow loss 下降放行。
  拟合门：对象平均 Chamfer 改善 >0，至少一半对象改善；同时报告 bootstrap CI，
  此工程门不表示统计显著性或泛化。失败时停止后续阶段，不自动扩量。

### 2026-10-20 修订003：表面采样密度复核

初版20K点、seed42的数据门完整保留于`data_gate.json`：15/16通过，i108的
F@.02=0.84955495，低于预设0.85；CD=0.01270393，通过0.015门槛。
在查看这一失败后进行的诊断发现，20K五种子的F@.02范围为0.847588–0.850282，
100K三个种子的范围为0.877601–0.879027。有限点云近邻距离会随采样密度变化，
不能把初版失败静默改成通过，也不能由此声称编码解码无损。

本次在任何16对象正式训练前，显式增加全体复核`data_quality_review.json`：
固定全部原16对象，各mesh均采样100K点，固定seeds 42/43/44；每个对象的
每个种子都必须满足原CD<=0.015、F@.02>=0.85门槛，同时保留坐标、SS、
目标投影检查，并显式检查全部输入视图的独立mask IoU>=.95。
不筛对象、不取最佳种子、不平均掩盖失败、不做任何几何拟合、不修改原mesh或latent。
原门失败且上述复核通过时，只放行本协议已有的官方对照及HSSD16可学习性诊断；
原门结果仍为失败，修订的时间、依据和所有结果随源码一起绑定。

这是看到初版失败后作出的工程协议修订，不能写成预先注册的初版成功。
父模型/候选模型的训练与完整采样评估仍使用原20K点等既定设置；100K复核
仅用于目标表示质量诊断，不替代论文主表，不自动授权扩量。

## 训练及评估队列

所有训练单 GPU、seed 20261020、有效 batch=1、lr=1e-4、warmup=20、constant、
uniform t、p_uncond=0。最终 raw 权重用于诊断，避免短训 EMA 延迟掩盖拟合。

1. 既有官方 target 的 Train32 前 16 对象作为阳性对照：LaRI 1000 步，
   SLat 200 步，固定真实支持，开启既有 attention LoRA 微调，验证完整 mesh 拟合。
   这是当前架构的新对照，不冒充 archive 的完全相同历史复现。
2. HSSD clean16：LaRI 1000，SLat 200（同阳性对照容量），SS full/no_layer 各500。
3. 同一 HSSD16 的原场景遮挡输入：独立从同一父模型初始化，预算同 clean16。

SLat 在原生目标支持上单独诊断；SS 对照的完整链路均使用同一个冻结父 SLat。
SS full/no_layer 共享输入、noise、更新数、初始化，full 的 LaRI 预训练单独计费，
不声称总计算量一致。LoRA 是数据可学习性诊断容量，不自动成为论文新贡献。

每个比较使用 seeds 42/43、25 步 SS（适用时）+25 步 SLat、相同 frozen decoder。
每个对象、每个 seed 都输出 GT/parent/candidate 的 4 视角同相机 mesh 对照图。
新 HSSD 的 GT 始终是原始资产几何；官方对照的 GT 是官方 latent 解码代理，分开报告。
不做 ICP、逐结果居中、缩放或旋转拟合。空 mesh 不可从统计中删除。
SS 与 SLat 联合适配的最终组合、独立场景/资产开发集、真实遮挡测试均不属于此次
自动放行范围，需要根据此轮结果继续设计。

## 使用

入口 `bash pose_aligned_layered_reconstruction/experiments/hssd_pilot_20261020/run.sh`。
`prepare --limit 1` 为单对象完整准备；`run` 顺序完成 16 对象准备及上述关卡/训练/评估。
`monitor --watch 10` 只读状态、进度、日志，不创建 CUDA 上下文。
同一命令支持已完成阶段复用及训练 last.pt 恢复；输入/源码冻结后不可混用修改版本。
`smoke` 在首个对象上验证 LaRI/两种 SS/SLat 各两次真实更新和四个完整25步 mesh；
`start` 在 smoke 通过后启动独立 systemd 用户服务，长队列可以脱离终端运行。
当前用户接管命令为 `start-preflight`：默认 GPU 2，依次补齐首对象准备、短训练/采样
smoke，然后才冻结并进入完整 16 对象队列。任何步骤失败立即停止，失败记录保留。
首对象已完成的 150 视角目标渲染、编码及场景 RGB/几何标签会复用，不从零重做。
如需指定其他单卡，启动前设置 `HSSD_GPU`；已经运行的服务不会因改环境变量迁移。
状态、阶段日志、completed 回执、图库均保留于独立输出目录。
